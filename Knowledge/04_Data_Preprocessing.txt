# 4.1 Introduction

Data preprocessing is one of the most important stages in any Machine Learning project. The performance of predictive models depends heavily on the quality of the input data. Raw datasets collected from real-world sources often contain missing values, duplicate records, inconsistent formatting, noisy observations, invalid entries, and irrelevant attributes. If these issues are not addressed before training, they can significantly reduce the accuracy, reliability, and interpretability of machine learning models.

In pharmacovigilance, adverse drug event reports are collected from multiple healthcare organizations, hospitals, pharmaceutical companies, physicians, pharmacists, and regulatory agencies. Since these reports originate from different sources, variations in data quality are common. Some reports may contain incomplete patient information, while others may include missing dosage values, duplicate submissions, or inconsistent naming conventions.

To ensure that the dataset used in the PharmaVigil AI project was suitable for predictive analysis, a comprehensive preprocessing pipeline was implemented. The preprocessing stage transformed the raw pharmacovigilance dataset into a clean, structured, and machine-learning-ready dataset.

The preprocessing pipeline improved the overall quality of the data, reduced inconsistencies, enhanced feature representation, and prepared the dataset for the Classification, Causality Assessment, and Regression models.

---

# 4.2 Objectives of Data Preprocessing

The primary objectives of preprocessing were:

- Improve overall data quality.
- Remove duplicate records.
- Handle missing values.
- Standardize feature formats.
- Convert categorical variables into numerical representations.
- Engineer new predictive features.
- Reduce data inconsistencies.
- Prepare separate datasets for different machine learning tasks.
- Improve model accuracy.
- Enhance explainability through SHAP.
- Ensure compatibility with Scikit-learn models.

These objectives ensured that the final dataset accurately represented the underlying pharmacovigilance problem.

# 4.5 Handling Duplicate Records

Duplicate records are common in pharmacovigilance datasets because adverse events may be reported multiple times by different sources.

Duplicate reports can lead to:

- Biased predictions.
- Overfitting.
- Incorrect statistical analysis.
- Misleading feature importance.
- Inflated reporting frequency.

To overcome these issues, duplicate records were identified and removed during preprocessing.

Benefits of duplicate removal include:

- Improved data quality.
- Better model generalization.
- Reduced redundancy.
- Faster model training.

---

# 4.6 Missing Value Analysis

Real-world healthcare datasets frequently contain missing information.

Common missing fields include:

- Patient Age
- Dose Amount
- Reporter Information
- Outcome
- Drug Information

Instead of deleting incomplete records, missing values were carefully analyzed.

The objective was to preserve as much information as possible while maintaining data quality.

---

# 4.7 Missing Value Treatment

Different preprocessing strategies were applied depending on the nature of the feature.

### Patient Age

Missing age values were handled without removing the corresponding records.

An additional binary feature named:

**is_missing_age**

was created.

Possible values:

- 0 → Age Available
- 1 → Age Missing

This allowed the machine learning model to learn whether missing age itself carried predictive information.

---

### Dose Amount

Similarly, missing dosage values were handled by introducing another binary indicator.

Feature:

**is_missing_dose**

Possible values:

- 0 → Dose Available
- 1 → Dose Missing

This strategy preserved incomplete reports while allowing the model to recognize missing dosage information.

---

### Advantages of Indicator Variables

Compared to deleting incomplete records, indicator variables provide several benefits:

- Preserve valuable observations.
- Reduce information loss.
- Improve robustness.
- Capture missing-data patterns.
- Improve explainability.

---

# 4.8 Feature Engineering

Feature engineering refers to the process of creating new variables that improve machine learning performance.

Instead of relying solely on raw dataset attributes, additional predictive information was generated.

The PharmaVigil AI project includes engineered features such as:

- Historical Adverse Event Frequency
- Missing Age Indicator
- Missing Dose Indicator

These engineered variables significantly improve prediction quality.

---

## Historical Adverse Event Frequency

Historical reporting frequency estimates how frequently similar adverse events have previously been associated with a particular drug.

This feature provides historical context.

Benefits include:

- Better seriousness prediction.
- Better causality prediction.
- Improved trend analysis.
- Improved SHAP explanations.

---

## Missing Indicators

The following binary indicators were generated:

- is_missing_age
- is_missing_dose

These features preserve information about incomplete reports instead of deleting them.

---

# 4.9 Categorical Encoding

Machine learning algorithms cannot directly process textual data.

Therefore, categorical attributes were converted into numerical values.

Examples include:

- Drug Name
- Country
- Reporter Type
- Batch ID
- Event Seriousness
- Causality Assessment

Label Encoding was used because it provides an efficient numerical representation while preserving class uniqueness.

The trained label encoders were saved separately and reused during deployment to ensure consistent predictions.

---

# 4.10 Numerical Features

The following numerical variables were retained:

- Patient Age
- Dose Amount
- Historical AE Frequency

These features were directly used during model training.

Numerical variables capture quantitative relationships between patient characteristics and adverse drug reactions.
