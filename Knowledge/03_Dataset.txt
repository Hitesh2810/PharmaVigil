# 3.1 Introduction

Data forms the foundation of every machine learning system. The quality, consistency, completeness, and relevance of the dataset directly influence the performance of predictive models. In pharmacovigilance applications, datasets consist of adverse drug event reports collected from healthcare professionals, hospitals, pharmaceutical companies, and regulatory authorities. These reports contain valuable information regarding drug usage, patient demographics, clinical outcomes, adverse reactions, and causality assessments.

For the PharmaVigil AI project, a pharmacovigilance dataset was developed to simulate real-world adverse drug event reporting. The dataset contains detailed patient information, drug information, reporting information, manufacturing details, dosage information, clinical outcomes, and adverse event characteristics.

Initially, the raw dataset consisted of approximately **9,000 adverse event records**. Since raw healthcare datasets often contain duplicate records, missing values, inconsistent formats, noisy entries, and irrelevant observations, extensive preprocessing was performed before model development.

The preprocessing pipeline included data cleaning, missing value handling, duplicate removal, feature engineering, label encoding, validation, and quality assessment. After preprocessing, the final curated dataset used for model training and evaluation contained **81 high-quality records** with **22 carefully selected attributes**. This cleaned dataset provided reliable input for the Classification, Causality Assessment, and Regression models implemented in this project.

The dataset serves as the primary source of information for all machine learning models developed in PharmaVigil AI.

# 3.6 Detailed Description of Remaining Dataset Attributes

The remaining attributes of the dataset provide additional clinical, manufacturing, treatment, and reporting information. These variables improve the predictive capability of the machine learning models and contribute to more accurate pharmacovigilance analysis.

---

## 11. adverse_event_term

### Description

The **adverse_event_term** represents the primary medical condition, symptom, or adverse reaction experienced by the patient after consuming the suspected drug.

This attribute records the clinical manifestation observed following drug administration.

Examples include:

- Headache
- Fever
- Skin Rash
- Vomiting
- Dizziness
- Nausea
- Liver Injury
- Kidney Failure
- Allergic Reaction
- Fatigue

### Importance

This is one of the most clinically significant variables because it directly represents the observed adverse reaction.

Different adverse events have different severity levels.

For example:

- Mild headache usually represents a low-risk event.
- Organ failure represents a serious adverse reaction.

Although the classification model primarily predicts seriousness using engineered features, adverse event terminology is important for pharmacovigilance analysis and future extensions.

### Data Type

Categorical

---

## 12. event_seriousness

### Description

This column represents the seriousness level assigned to each adverse drug event.

Possible values include:

- Serious
- Non-Serious

### Purpose

This column is used as the **target variable** for the Classification Model.

The machine learning model learns relationships between patient information and seriousness labels.

### Importance

This attribute is one of the primary outputs of the pharmacovigilance platform.

Predicting serious adverse events helps healthcare professionals prioritize investigations and improve patient safety.

---

## 13. outcome

### Description

The outcome column represents the final clinical status of the patient following the adverse event.

Possible examples include:

- Recovered
- Recovering
- Not Recovered
- Fatal
- Unknown

### Importance

Patient outcome provides valuable insight into the clinical impact of adverse drug reactions.

Although outcome is not always used as a prediction feature, it is valuable for exploratory analysis and visualization.

### Data Type

Categorical

---

## 14. onset_date

### Description

This attribute records the date on which the adverse event first appeared after drug administration.

### Importance

The onset date enables temporal analysis.

Researchers can calculate:

- Time to onset
- Reporting delay
- Weekly adverse event counts
- Monthly trends

The regression module benefits from time-related information derived from onset dates.

### Data Type

Date

---

## 15. batch_id

### Description

Batch ID identifies the manufacturing batch of the suspected pharmaceutical product.

### Importance

Manufacturing defects sometimes affect only specific production batches.

Including batch information enables detection of batch-specific safety signals.

The Classification and Causality models use encoded batch identifiers as predictive features.

### Data Type

Categorical

---

## 16. manufacturing_site

### Description

The manufacturing_site column specifies where the pharmaceutical product was manufactured.

### Importance

This feature supports pharmacovigilance investigations involving manufacturing quality.

It can assist regulatory authorities in identifying production-related issues.

### Data Type

Categorical

---

## 17. dose_amount_mg

### Description

This attribute records the dosage administered to the patient.

The value is represented in milligrams (mg).

### Importance

Drug dosage significantly influences adverse reaction probability.

Higher dosages may increase toxicity risk.

Lower dosages may produce fewer adverse effects.

Consequently, dose amount is an important predictive feature.

### Data Type

Numerical

---

## 18. is_missing_dose

### Description

Binary indicator showing whether dosage information was missing in the original dataset.

Possible values:

0 → Available

1 → Missing

### Importance

Instead of deleting incomplete records, missing information is preserved using indicator variables.

This approach improves model robustness while minimizing information loss.

### Data Type

Boolean

---

## 19. route_of_administration

### Description

Specifies how the drug entered the patient's body.

Examples include:

- Oral

- Intravenous

- Intramuscular

- Topical

- Subcutaneous

### Importance

Drug absorption varies significantly across administration routes.

Route differences may influence adverse event occurrence.

### Data Type

Categorical

---

## 20. concomitant_medications

### Description

Represents additional medications consumed simultaneously with the suspected drug.

### Importance

Drug-drug interactions are among the leading causes of adverse reactions.

Including concomitant medications improves future pharmacovigilance analyses.

### Data Type

Categorical

---

## 21. causality_assessment

### Description

Represents the likelihood that the reported adverse event was caused by the suspected drug.

Typical classes include:

- Certain

- Probable

- Possible

- Unlikely

- Unassessable

### Importance

This column serves as the target variable for the Causality Prediction Model.

The model learns to estimate causality using patient demographics, drug information, dosage, reporting information, and historical frequencies.

### Data Type

Categorical

---

## 22. historical_ae_frequency

### Description

Historical adverse event frequency represents the historical occurrence rate of similar adverse events associated with the reported drug.

### Importance

Historical reporting frequency provides contextual knowledge.

Drugs with historically high adverse event frequencies may demonstrate increased prediction probabilities.

This engineered feature improves predictive performance.

### Data Type

Numerical

# 3.8 Dataset Used in the Project

The project initially began with a pharmacovigilance dataset containing approximately **9,000 adverse drug event reports**.

Large real-world healthcare datasets typically contain:

- Duplicate records
- Missing values
- Inconsistent entries
- Noisy observations
- Invalid records
- Incomplete reports

Such issues reduce the effectiveness of machine learning models.

Therefore, a comprehensive preprocessing pipeline was implemented to improve data quality.

The preprocessing included:

- Duplicate removal
- Missing value treatment
- Feature engineering
- Data validation
- Data standardization
- Label encoding
- Quality verification

# 3.9 Why Dataset Cleaning Was Necessary

Machine learning algorithms assume that the training data accurately represents the underlying problem.

Raw healthcare datasets frequently contain inconsistencies that negatively affect model performance.

The primary reasons for cleaning the dataset include:

- Eliminating duplicate reports.
- Correcting inconsistent formatting.
- Handling missing values.
- Removing invalid observations.
- Improving prediction accuracy.
- Reducing model bias.
- Enhancing explainability.
- Producing reliable evaluation metrics.

Without preprocessing, model predictions may become unreliable and difficult to interpret.
